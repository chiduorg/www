## 0. 一句话方案

**元素站从“周期表知识页”改成「原子剧场」：拖动的不是卡片，而是质子数 Z。**  
**质量站从“纵向文字阶梯”改成「质量深渊」：拖动的不是滚动条，而是 10⁻⁴⁰ → 10⁵³ kg 的对数深度。**

两站都不另造一套交互，直接接入时间站、温度站已经在用的 `station` 骨架：左侧章节 / 中间 3D 舞台 / 右侧当前条目卡 / 底部尺度控制台 / 图文阅读模式。这样用户在前三站学会的“拖动、旋转、巡游、看读数”可以直接迁移过来。

## 1. 现状判断：为什么现在像“知识介绍页”

| 站点 | 当前形态 | 页面长度 | 交互 | 问题 |
|---|---|---|---|---|
| 元素 | hero + 七级壳层阶梯 + 18 列周期表 + 下方详情卡 | 约 4,340 px | 点格子、方向键换 Z | 先读 118 条事实，再看到表格；没有连续变化的视觉主体 |
| 质量 | hero + 纵向 16 带文字阶梯 + 三种口径 + 覆盖带清单 | 约 10,170 px | 点条目、滚动阅读 | 16 带是一条很长的列表；质量差异只体现在数字和文字上 |

对比前三站：

- 空间：`space/src/app.js` 用 Three.js + 模型/环境模块，支持旋转、缩放、模型切换、30 秒巡游。
- 时间：`time/src/demo.js` 用 `renderer.createViewport($('station-canvas'))`，滑块驱动 `scene.setEntry`，有动态、巡游、沉浸模式、图文模式。
- 温度：`temperature/src/demo.js` 同一套骨架，滑块驱动温度场景，支持 K/°C、动态、巡游。

元素和质量目前都**没有 canvas / Three.js 主舞台**；构建里的 Three.js vendor 复制条件也只覆盖 `space/time/temperature`。所以差距不是文案，而是“缺少一个可连续变化、可拖动、占据首屏的视觉主体”。

两站还各有一个顺手要修的小问题：`elements/src/index.html` 与 `mass/src/index.html` 没有加载 `/brand.js`，所以顶部仍会出现重复的“知识库 ↗”。这属于整合时一并处理的 UI 基础项，不是本次方案的核心。

## 2. 设计原则

1. **先舞台，后知识。** 首屏是 3D/Canvas 舞台，文字退到左栏、右卡和下方阅读层；不再用 hero + 长文占据第一屏。
2. **一个连续变量驱动一个场景。** 元素 = Z（1→118，整数）；质量 = log₁₀(m/kg)（-40→53，连续）。拖动时场景连续变化，松手后吸附到最近元素/条目。
3. **不伪造“真实外观”。** 元素的核与壳层是示意；质量的物体同视尺寸，差异由对数尺和引力场表达，不由体积表达。所有示意都在屏幕上写明。
4. **复用现有骨架，不重做站点。** 用 `engine/ui/station.js`、`fallback.js`、`renderer.createViewport`，与时间/温度保持同一套操作语言。
5. **保留现有内容与 URL。** 文章页、sitemap、知识库、1354 条内容不动；只改元素/质量首页的首屏与交互层，下面保留“知识层”。

### 3.2 舞台怎么“变”

以 Z 为唯一输入，场景分三层：

**① 核：质子与中子**

- 质子数 = Z；中子数 = `massNumber − Z`（用现有 `properties[z].massNumber`，不引入新数据）。
- 用 InstancedMesh 小球做“核子堆”：质子暖色、中子冷色；Z 越大，核越挤、越亮。
- 对 `predicted: true` 的超重元素，核子用虚线/半透明描边，右卡标“预测”。
- 对没有稳定同位素的元素，右卡把 massNumber 的口径写清楚（“最长寿命同位素/预测值”），不把它说成自然丰度。

**② 壳：电子排布**

- 七个主壳层做成七圈倾斜的轨道环；每个环再按 s/p/d/f 分成弧段，标 `1s`、`2p`、`3d`、`4f`……
- 电子用发光点表示，数量来自 `configuration`；不是“行星绕太阳”，而是“壳层占据示意”。
- 每当 Z 增加：
  - 新电子进入当前亚层，弧段亮一下；
  - 闭壳节点（2/10/18/36/54/86/118）整圈锁住，发一次脉冲；
  - 碱金属（Li/Na/K/Rb/Cs/Fr）最外层新环点燃，提示“新层开始”；
  - 过渡金属填 3d/4d/5d 时，内层弧段补充，而不是最外层变亮。
- 屏幕固定角标：“原子核与壳层为示意；核半径被放大，电子不沿固定轨道运动。”

**③ 场：性质趋势**

舞台底部叠三条细曲线（不是 3D，SVG/Canvas 2D 即可）：

- 第一电离能（eV）
- 原子半径（pm）
- 电负性（Pauling）

当前 Z 用一条竖直光带标记；拖动时曲线跟着走，右卡同时显示“相对 Z−1”的差值。这样“闭壳处电离能尖峰、碱金属处跌落、同周期半径收缩”不只靠文字解释，而是肉眼可见。

### 3.3 交互

- **拖动底部 Z 尺**：连续换 Z；松手吸附到整数；`input` 事件即时更新，`requestAnimationFrame` 合并渲染。
- **在舞台上拖动**：旋转原子；滚轮换 Z（与时间/温度一致）；双击复位。
- **键盘**：`←/→` 或 `↑/↓` 步进 Z；`Home/End` 到 H/Og；`Space` 暂停/继续巡游；`Esc` 退出沉浸。
- **周期表**：点击格子 → 舞台相机飞向该元素，右卡更新；周期表仍可当导航地图。
- **巡游**：从 H 自动走到 Og，约 30 秒；在闭壳节点停顿 1.2 秒，在碱金属节点闪一下；可暂停。
- **比较模式（第二阶段可选）**：固定 A/B 两个元素，左右两个原子并排；下方只显示“多了几个质子/电子、哪层填满、三项性质差多少”。不默认开启，避免首屏复杂。

### 3.4 数据使用

现有 `dist/elements/elements.json` 已经够 v1：

- `elements[]`：`z`、`symbol`、`nameZh/nameEn`、`period`、`group`、`block`、`closedShell`、`predicted`、`configuration`
- `properties[z]`：`ionization`、`radius`、`radiusKind`、`electronegativity`、`massNumber`、`stableIsotopes`、`isotopeNote`
- `entries.json`：`category`、`summary`、`title`、`visual`、文章链接

不需要新增密度、熔点、沸点、原子量小数。那些属于“元素性格/实物外观”的另一次内容补全，不在本轮伪造。若以后要加，必须逐条补来源，不能凭模型生成。

## 4. 质量站：质量深渊 / THE MASS DESCENT

### 4.1 为什么不是“把物体按质量放大”

质量不是体积，也不是重量。一个 1 kg 的铁块、1 kg 的水、1 kg 的羽毛，外观完全不同但质量相同；如果按质量直接放大物体，会教错。质量站在数据里也**没有**统一的尺寸/密度字段。

所以主舞台不表达“大小”，而表达**对数深度**：

- 16 个覆盖带 = 16 层“深渊”；
- 拖得越深，质量越大；
- 物体保持同视尺寸（便于看清），差异由深度、引力场、参照倍率和读数表达；
- 屏幕固定角标：“物体为同视尺寸示意；质量差异由对数尺与引力场表达，不由体积表达。”

### 4.3 舞台怎么“变”

**① 深渊层：16 个带**

- 每一层有独立的雾色、环境光、背景纹理：B1 冷紫、B7 暖白、B13 金橙、B14 深黑+引力环、B16 深蓝宇宙网。
- 相机沿纵轴下潜；当前带的对象在中心，上一层/下一层的对象在远处作为“路标”。
- 带与带之间不是硬切，而是 0.8–1.2 秒的过渡：雾色、光、粒子密度渐变。
- 左侧章节列表随深度高亮；底部刻度显示当前 log 值和带内位置。

**② 对象层：16 类程序化原型**

不为 146 条各做模型。按 `category` + `id` 映射到 16 类程序化原型：

- `particle`：发光点/波纹
- `nucleus`：核子团
- `atom`：核 + 电子壳
- `molecule`：球棍/链状结构
- `virus`：二十面体 + 刺突
- `cell`：半透明膜 + 内部细胞器
- `grain`：不规则微粒
- `human`：简化人形剪影
- `object`：日常物品（硬币/回形针/钢琴等，按 id 细分）
- `architecture`：塔/桥/坝的线框剪影
- `vehicle`：车/船/飞机
- `landscape`：山体/水体
- `planet`：球体 + 大气层
- `star`：发光球 + 日冕
- `compact`：白矮星/中子星/黑洞（黑洞有吸积盘与透镜环）
- `cosmos`：星系盘/星系团/宇宙网

所有原型用 Three.js 基础几何 + InstancedMesh 程序化生成，不引入外部 3D 资产；与空间站的 `object-templates.js` 同一路线，避免授权与下载体积问题。

**③ 引力层：质量越大，井越深**

- 舞台地面是一张可变形的时空网格；质量越大，网格下陷越深、引力透镜环越明显。
- 低质量区（B1–B6）：网格几乎平的，只有轻微量子抖动；
- 行星/恒星区（B11–B13）：明显弯曲，出现轨道粒子；
- 黑洞/星系区（B14–B16）：强透镜、吸积盘、星系旋转。
- 井深按 `log10(mass)` 映射，屏幕标注“引力势示意，深度为对数压缩，不是实际空间曲率”。

**④ 读数层：让“差别”可量化**

右卡与底部始终显示：

- `displayValue`（条目原有读数，保留 ≤/≥/≈ 前缀）
- `quantity.measure`（口径：静质量/总质量/重子质量/恒星质量/动力学质量）
- `mass.includesDarkMatter`（含/不含暗物质）
- `mass.method`、`mass.uncertainty`（有则显示）
- 参照倍率：与成人（70 kg）、地球（5.972×10²⁴ kg）、太阳（1.989×10³⁰ kg）的 `×10ⁿ` 关系
- 零质量特例：光子不进入深渊排序，单独一个“光”场景，显示实验上限；不画成有质量的点。

### 4.4 交互

- **拖动底部对数尺 / 在舞台上纵向拖动**：下潜或上浮；松手吸附到最近条目；滚轮换深度。
- **点击左栏 16 带**：相机飞到该带第一个有数据的锚点；没有数据的十进位保持“待补入”，不填占位值。
- **条目选择器**：146 条按质量排序，可搜索；选择后相机自动下潜。
- **巡游**：从 B1 到 B16 自动下潜，约 40 秒；在每个带起点停顿，在黑洞口放慢；可暂停。
- **同质量不同物体（教学卡，可选）**：1 kg 铁块 / 1 kg 水 / 1 kg 羽毛，三个外观不同的物体放到同一台秤上，读数都为 1 kg。用来纠正“质量=大小/重量”的误解，不占主舞台。
- **比较模式（第二阶段可选）**：选 A/B 两个对象，只显示质量倍率、口径差异、是否含暗物质；不做“体积对比”。

### 4.5 数据使用

现有 `dist/mass/entries.json` 146 条够 v1：

- `id`、`title`、`summary`、`category`、`displayValue`
- `quantity.value`、`unit`、`measure`、`approximate`、`bound`
- `mass.type`、`includesDarkMatter`、`method`、`uncertainty`
- `zeroMass`

不需要新增尺寸/密度。原型的映射放在 `mass/src/subjects.js`（代码映射，不改内容快照）；如果以后要把“原型”变成内容字段，再给 146 条补 `visual.archetype`，那是独立的内容任务。

## 5. 两站共用的工程改造

### 5.1 骨架复用

- `engine/ui/station.css` 的 `station-main`、`station-rail`、`station-card`、`station-console`、`station-backdrop` 布局

元素/质量只需要新增各自的 `scene.js` 与数据映射；不改时间/温度/空间。

### 5.2 新增文件（草案）


### 5.3 构建

`engine/packages/build/index.mjs` 目前：

```js
if(['space','time','temperature'].includes(site)){ ...复制 three.module.js / three.core.js... }
```

需要改成包含 `elements`、`mass`：

```js
if(['space','time','temperature','elements','mass'].includes(site)){ ... }
```

同时给两站 HTML 加 importmap：

```html
<script type="importmap">{"imports":{"three":"/vendor/three.module.js"}}</script>
```

首屏不加载 Three.js；`demo.js` 在 `load` 后 `requestIdleCallback` 里动态 `import('three')` 和 `scene.js`，与时间/温度一致。移动端延迟 2.5 秒再初始化，失败或无 WebGL 时自动切图文模式。

### 5.4 顺带修复

- 两站 `<head>` 加 `<script type="module" src="/brand.js"></script>`，让品牌名、页脚、重复“知识库 ↗”与其它站一致。
- 两站 `index.html` 现在没有 `brand.js`；这是当前 8084/8085 页面仍显示重复导航的直接原因。
- 这属于整合时一并处理的小修，不单独发版。

### 5.5 性能与降级

- 核子、电子、粒子用 InstancedMesh；对象原型用低面数几何；不用外部模型/贴图。
- `renderer` 像素比上限沿用现有 viewport 策略；页面隐藏时暂停 `requestAnimationFrame`。
- `pagehide` dispose 场景；`viewport-lost` 切图文模式（与时间/温度一致）。
- 首屏静态内容仍可读；`noscript` 保留。
- `prefers-reduced-motion` 时默认不自动巡游，拖动仍可用。

### 5.6 可访问性

- canvas 有 `aria-label`，右卡是 `aria-live="polite"`；拖动时只更新文本，不连续刷屏。
- 底部滑块是原生 `input[type=range]`，带 `aria-valuetext`（“Z=1，氢，1s¹” / “5.972×10²⁴ kg，地球”）。
- 键盘可完成全部选择；周期表/带列表仍可 Tab 到达。
- 对比度、焦点环、`prefers-reduced-motion` 纳入 axe 检查。
- 图文模式保留完整文字，不把信息只放在 canvas 里。

## 6. 分期与取舍

### 方案 A（推荐）：3D 舞台，接现有 station 骨架

- 与前三站同源，沉浸感最强。
- 元素用参数化原子，质量用 16 类程序化原型；不需要 118/146 个独立模型。
- 代价：两站各增加一个 `scene.js`，three.js vendor 多复制两份（静态域仍共用一份）。

### 方案 B：2D Canvas / SVG 舞台

- 更轻、更稳、移动端更好；元素壳层和趋势线用 2D 也能很清楚。
- 但观感与前三站不完全同源，空间感弱；质量深渊的纵深感会打折。
- 如果 3D 原型性能不达标，可作为降级层，而不是主方案。

### 方案 C：只加 CSS 动效和转场

- 成本最低，但不解决“没有视觉主体”的问题；不推荐作为主方案。

### 建议顺序

1. **先元素，后质量。** 元素的视觉逻辑最确定（Z、壳层、趋势都是现成数据），做完就能验证“station 骨架 + 参数化 3D”这条路。
2. 元素原型先给用户看感觉；确认后再做质量深渊。两站同时开工容易在“质量怎么表达”上返工。
3. 比较模式、同质量教学卡、元素“电子云模式”放第二阶段，不塞进首版。

## 8. 风险与边界

| 风险 | 处理 |
|---|---|
| 3D 原子被误读为“电子绕核行星模型” | 不用电子小球绕行；改用 s/p/d/f 概率云与半透明瓣面，细环只作壳层尺度参考，并在舞台内与脚注写明“不是轨道”“现代量子模型没有确定轨迹” |
| 质量站被误读为“物体越大质量越大” | 物体同视尺寸；质量只用对数尺、引力井、倍率表达；加“同质量不同物体”教学卡 |
| 118/146 个独立模型导致体积爆炸 | 元素参数化；质量 16 类原型；全部程序化几何，无外部资产 |
| Three.js 增加首屏负担 | 动态 import；首屏静态内容先到；移动端延迟；失败降级 |
| 元素数据没有密度/熔点/颜色 | 不伪造；本轮只用现有 Z、构型、电离能、半径、电负性、massNumber |
| 质量数据没有尺寸/密度 | 不做体积对比；不按密度反推；需要时另立内容补全任务 |
| 两站同时改导致返工 | 先元素原型，确认“station + 参数化 3D”感觉后再做质量 |
| 当前重复“知识库 ↗” | 两站加载 `/brand.js`，与其它站一致 |
